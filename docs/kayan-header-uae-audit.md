# لماذا الهيدر مكسور؟ وبقايا الإمارات في قالب KAYAN

**الموقع:** https://www.rukn-eltatawer.com/bh  
**القالب الحي:** `kayan-theme` **1.4.28** (كان 1.4.12 في فحص 17 سبتمبر)  
**ووردبريس / PHP:** 7.1 / 8.3.33  
**تاريخ الفحص:** 23 سبتمبر 2026  
**النطاق:** ملفات القالب عبر WPVibe + HTML حي + لقطات سطح مكتب/موبايل. **لم يُعدَّل القالب** (`editable: false`).

طبقة الترقيع الحالية: سكربت Code Snippets **id 5** «Rukn BH Live Fixes» — يحقن CSS/HTML فوق القالب ولا يصلّحه من المصدر.

## الخلاصة

الهيدر مكسور لأن القالب يشغّل **نظامي تصميم في وقت واحد**:

1. **YourColor القديم** (`main.css` / `responsive.css`): شريط أبيض عبر `header::before`، و`header{left:0}` داخل selector مجمّع، و`flex-wrap:wrap`.
2. **Rukn v3 الجديد** (`#hdr` + `rukn-v3.css`): هيدر شفاف بعرض كامل يحاول إلغاء `::before`.

سكربت البحرين يحاول إخفاء الشريط الأبيض بـ `!important`، لكنه يُطبع في `wp_head` **قبل** أن يصبّ القالب `main.css` في `<style>` ضخم. على الموبايل الشريط الأبيض ما زال ظاهراً في اللقطة الحية.

بقايا الإمارات ليست في إعدادات الفوتر الظاهرة فقط: هي **افتراضات ودجات وبذور وخريطة SVG** داخل ملفات القالب.

## 1) لماذا يظهر الهيدر مكسوراً؟

### 1.1 الشريط الأبيض — `header::before`

في `components/styles/main.css` (CSS مضغوط، سطر 1) القاعدة الأصلية:

```css
header:before{
  content:"";
  position:absolute;
  width:100%;
  height:100%;
  background:#fff;
  right:0;
  opacity:1;
  top:0;
  transform:translateY(0);
}
```

هذه طبقة بيضاء فوق الهيدر صُمّمت لنسخة «هيدر فاتح على سلايدر». إخفاؤها يعتمد على class `fixedintro`:

```css
header.fixedintro::before{visibility:hidden;opacity:0}
header.fixedintro::before{transform:translateY(-100%)}
```

ثم **يُعاد إظهارها** بمحددات مجمّعة (خطأ تجميع CSS):

```css
.--Site--Menu>ul>li: hover>ul.sub-menu,
header::before{
  transition:280ms;
  transform:translateY(0);
  visibility:visible;
}
```

وعلى شاشات الموبايل داخل نفس حزمة الستايل:

```css
header.fixedintro::before{
  transform:translateY(0);
  opacity:1;
  visibility:visible;
}
```

النتيجة: شريط أبيض بعرض الهيدر (أو جزء منه). هذا يطابق شكوى «شريط أبيض بعرض نصف الهيدر».

`rukn-v3.css` يحاول القتل:

```css
header::before{content:none!important;display:none!important}
```

سكربت 5 يكرر القتل في `#rukn-bh-ui`. **اللقطة الموبايل بتاريخ 23 سبتمبر ما زالت تُظهر شريطاً أبيض أعلى الشاشة** واللوجو فوقه. الترقيع لا يكفي لأن:

- ترتيب الطباعة: `wp_head` (السكربت) ثم `<style>` العملاق (`main` ثم `responsive` ثم `rukn-v3`).
- `body{background:var(--bg)}` من v3 (`--bg:#F4F8FD` فاتح) يلغي `html,body{background:#0A1F4E}` الذي وضعه السكربت لإخفاء فراغ أندرويد.
- الهيدر `background:transparent` فيثبت الأبيض/الفاتح من الطبقة أو من `body`.

### 1.2 الهيدر ينزاح لنصف العرض — `header{left:0}`

محدد مجمّع في `main.css`:

```css
.-YC-owl-navs-items>.-YC-owl-Slides-next,
header{left:0}
```

هيدر RTL ثابت كان `right:0` بلا `width:100%`. ضبط `left:0` دون `right:0` يجعل الصندوق يلتصق باليسار بعرض المحتوى ≈ **نصف الشريط**. السكربت يضيف:

```css
header,header#hdr,header.fixedintro{
  left:0!important;right:0!important;inset-inline:0!important;width:100%!important;
}
```

هذا علاج عرض لا إصلاح المصدر.

### 1.3 `flex-wrap:wrap` يفصل صفاً أبيض

القواعد القديمة: `header{flex-wrap:wrap}`. إذا ضاق الصف (لوجو + 7 روابط + بحث + لغة + واتساب + هامبرغر) يلفّ الصف الثاني ويظهر كشريط. v3 والسكربت يفرضان `nowrap`.

### 1.4 حرف إنجليزي يتسرب: `n` أعلى اليمين

في لقطتي سطح المكتب والموبايل يظهر حرف **`n`** أعلى يمين الهيدر فوق اللوجو. هذا بقايا عنصر لغة/قائمة (`English` أو `.rukn-lc-langico en`) بعد `overflow`/`display`. رابط اللغة في الهيدر يذهب إلى `/bh/en/` (**404**). عنصر القائمة «English» يفتح `/home-services-bahrain/` — مساران مختلفان.

### 1.5 القائمة كانت تُرسم فارغة

`#header/part.php` يبني `<nav class="menu">` من `wp_get_nav_menu_items` يدوياً (ليس `wp_nav_menu`). `MenuField` يفلتر عناصر في الرئيسية. السكربت إن وجد `<nav class="menu"></nav>` يحقن روابط ثابتة. اليوم القائمة مملوءة في HTML، لكن الموبايل `#ruknMob` فيه **روابط مكررة** (حقن السكربت + حلقة القالب).

### 1.6 لوجو وويب أبيض (طبقة ثانية من «الشريط»)

سابقاً الملف `20260417_163942_٠٠٠١.webp` بخلفية بيضاء في الميتاداتا رُسم كشريط على سامسونج. السكربت يستبدل المصدر بـ `rukn-logo-transparent.webp` ويخفي `.logo .mark` و`<b>`. إن فشل التحميل (`onerror`) يختفي اللوجو ويظهر نص بديل — وهذا ما حدث عندما «اختفى اللوجو».

### 1.7 لماذا يبدو مكسوراً حتى بعد الترقيع؟

| العَرَض | السبب في القالب | ماذا يفعل السكربت 5 |
|---|---|---|
| شريط أبيض | `header:before{background:#fff}` + إعادة إظهاره على الموبايل | `content:none!important` — **غير كافٍ على الموبايل الحي** |
| نصف عرض | `header{left:0}` مجمّع مع زر سلايدر | `left/right/width 100% !important` |
| لوجو مقطوع/داكن | `overflow` + `mix-blend` سابقاً | mix-blend:normal عند `.scrolled` |
| قائمة فارغة | فلاتر MenuField + رسم يدوي | حقن HTML إن كانت فارغة |
| حرف `n` | مفتاح لغة / عنصر English | غير مُعالَج |
| تداخل مع الهيرو | هيدر ثابت شفاف بلا `padding-top` كافٍ على `root` | غير مُعالَج |
| واتساب الهيدر يختفي موبايل | مقصود في CSS v3 (`nav-cta .btn`) | يخفيه تحت 768px |

**الإصلاح الجذري (في القالب الإماراتي القادم أو في KAYAN):** حذف `header::before` من `main.css`، فكّ `header` من محددات Owl المجمّعة، هيدر واحد (v3 فقط)، وإيقاف سكربت الترقيع بعد ذلك.

## 2) بقايا الإمارات داخل ملفات القالب

البحث عبر WPVibe داخل `kayan-theme` (23 سبتمبر 2026). الفوتر الحي يظهر «المنامة» لأن السكربت يستبدل النص عند الإخراج؛ **المصدر ما زال إماراتياً**.

### 2.1 ودجات بمدن الإمارات (تظهر إن فُعّل المحتوى الافتراضي)

| ملف | البقايا |
|---|---|
| `city__widget.php` | تعليق التصميم: «خدماتنا في جميع إمارات الدولة». افتراضي يدوي: **دبي، أبوظبي، الشارقة، عجمان، رأس الخيمة، الفجيرة**. SVG `class="uae-svg"` **ثابت** حتى لو المدن بحرينية |
| `city__widget.css` + `rukn-v3.css` | تنسيق `.uae-svg` (خريطة الإمارات) |
| `Faqs__simple2.php` | «هل تعملون في جميع إمارات الدولة؟» + السبع إمارات؛ «تكلفة كشف تسربات المياه في الإمارات» |
| `rukn_cases.php` / `kayan-seed/setup.php` | «فيلا — دبي مارينا» |
| `rukn_reviews.php` | تقييمات نموذجية من «دبي مارينا» |
| `works.php` / `rukn_results.php` | أمثلة موقع دبي مارينا |
| `slider_intro_v1.php` | «معتمد من بلدية دبي» |
| `rukn_finder.php` | «الخدمة + الإمارة» في الوصف وحقول المحرّر |
| `kayan-booking.js` | حقل `emirate` / «الإمارة / المنطقة الرئيسية» |
| `kayan-i18n/content-map.php` | ترجمات: اختر الإمارة، رخصة بلدية دبي، عضوية الغرفة… |

الحي على الرئيسية: CSS `.uae-svg` موجود (5 مرات). JS السكربت ما زال يبحث عن `اختر الإمارة` و`دبي، الإمارات` ليستبدلها — دليل أن القالب ما زال يطبعها قبل الترقيع.

### 2.2 هوية وهاتف

- خيارات القالب `whatsapp_number` و `phonenumber` يضبطها السكربت على **`+971586634710`**.
- Schema القالب `LocalBusiness` ما زال **فارغاً** (`YourColoe_Schema_business` — خطأ إملائي Color). السكربت يضيف كتلة ثانية بهاتف إماراتي وعنوان المنامة.
- فوتر القالب يطبع `get_option('company__adress')` كما هو؛ السكربت يستبدل «دبي، الإمارات…» عند الإخراج فقط.
- رابط مطوّر `wa.me/201151481000` يُستبدل بـ «KAYAN WEB» في HTML — الرقم المصري لم يُحذف من القالب/الخيارات.

### 2.3 i18n ما زال خليجياً

- نطاق النص `yourcolor` لا `kayan`.
- `kayan_i18n_fallback_country_code()` إن فشل الخيار يأخذ أول دولة `path === ''` — في خريطة الدول تلك هي **الإمارات (`ae`)** على الشبكة، بينما البحرين `/bh`. السكربت يصفر `bh.path` لتفادي `/bh/bh/`.
- مفتاح اللغة في الهيدر → `/bh/en/` 404.

## 3) أخطاء ونواقص أخرى في القالب (غير الشريط)

### حرج

- لا `404.php` / `single.php` / `page.php` في الجذر. المحرّك `ThemeStatic::Locate()` ثم `die()`.
- أرشيفات CPT كانت 500؛ السكربت يحوّلها لـ 404 يدوي. القالب ما زال يسجّل `has_archive` للأنواع الفارغة.
- Rank Math معطّل على الواجهة (`kayan-seo/compatibility.php`) ثم Schema يدوي فارغ + `aggregateRating` فارغ.
- Ajax بلا nonce، `RateAjax` مفتوح، `Currentuser_Logged = true` دائماً في الفوتر JS (من التدقيق السابق؛ المعمارية لم تتغير).
- `echo $item->url` في القائمة بلا `esc_url` — XSS مخزّن.
- `header___codes` يُطبع خام في `<head>`.

### نواقص يحتاجها القالب البحريني (أو النسخة الإماراتية المنسوخة مع ضبط دولة)

- خريطة SVG بحرين (أو لا خريطة دولة) بدل `.uae-svg`.
- ودجات افتراضية بمدن البحرين لا الإمارات.
- FAQ/بذور/تقييمات بدون دبي مارينا وبلدية دبي.
- حقل «مدينة» لا «إمارة» في `rukn_finder` والحجز.
- Schema واحد مملوء (اسم، +973 لاحقاً، المنامة، BH) بلا AggregateRating وهمي.
- `language_attributes()` أو `kayan_i18n_get_html_attrs()` فقط — الحي حالياً `lang="ar"` وهذا جيد إن بقي.
- قائمة عبر `wp_nav_menu` وموقع فوتر قياسي.
- تحييد كامل لـ `main.css` على `header` بدل ترقيع بعد الطباعة.

### تعارضات تصميم v3 × القديم

- وسم `<root>` كان `display:flex` فاختفى المحتوى؛ v3 يفرض `display:block`. أي صفحة تفوّت هذه القاعدة تنكسر.
- jQuery 3.4.1 + CSS inline ضخم (~300 ك.ب ستايل في الرئيسية).
- أخطاء إملائية باقية: `passowrd` في `forms.css`، `YourColoe`، `defualt_*`.

## 4) ماذا سيحدث عند نسخ قالب الإمارات؟

إن نُسخ قالب الإمارات «بعد اكتمال تطويره» إلى `/bh/` دون تنظيف:

- ودجات المدن/الخريطة/FAQ ستعيد الإمارات ما لم تُضبط الدولة والمحتوى الافتراضي على بحرين.
- هيدر v3 مقابل `main.css` سيُعاد إن بقيت الطبقتان.
- سكربت 5 سيتعارض مع قالب جديد إن لم يُوقف.

**قبل النسخ:** قائمة تنظيف في القالب المصدر (الإمارات) لوحدات الدولة (خريطة، مدن افتراضية، FAQ، بذور، finder، booking، schema). ثم على البحرين: إيقاف Snippet 5 بعد التحقق أن الهيدر لا يستخدم `::before` ولا `header{left:0}` المجمّع.

## 5) أولوية إصلاح الهيدر (إن لزم قبل استبدال القالب)

1. في `main.css` / `responsive.css`: حذف قاعدة `header:before` البيضاء بالكامل، وحذف `header` من محدد Owl المجمّع.
2. التأكد أن `rukn-v3.css` يُحمَّل آخراً وأن `header{inset-inline:0;width:100%;flex-wrap:nowrap;background:transparent}` بلا `::before`.
3. إخفاء حرف `n` (overflow على مفتاح اللغة أو عنصر English المخفي).
4. توجيه مفتاح EN إلى صفحة إنجليزية موجودة لا `/bh/en/`.
5. بعد استقرار الهيدر: إزالة CSS الهيدر من Snippet 5 حتى لا تُدار الحرب من مكانين.

لم يُغيَّر القالب الحي في هذا الفحص.
